# 金融 Demo 场景与界面设计

本文说明当前七个场景的输入、结果和演示内容。执行模式、Problem API 组件和模式选择规则见[金融 Demo 架构设计](finance_problem_api_architecture.md)。

## 演示范围

Demo 面向银行、证券、基金和金融科技客户。所有数据均为合成数据，运行使用 CASCAQit 本地模拟器。业务页回答“选择了什么、约束是否满足”，量子页回答“Problem 如何映射、执行了什么程序、采样得到什么”。

七个场景提供 21 个预设：

| 场景 | 预设 |
|---|---|
| 投资组合 | 基准市场、利率上行、权益回撤、商品冲击 |
| 交易结算 | 日常批次、流动性收紧、重点客户优先 |
| 调查编排 | 账户接管、团伙交易、商户异常 |
| 抵押品分配 | 日常补缴、市场波动、保留优质资产 |
| 流动性调度 | 基准流动性、跨币种短缺 |
| 授信额度 | 稳健配置、收益优先 |
| 衍生品 | 欧式看涨、欧式看跌、亚式期权、上敲出障碍期权 |

预设只改变当前业务输入。切换预设后，应用重新构造并分析 Problem，不复用固定量子结果。

## 场景设计

### 多资产投资组合

默认数据包含 8 类合成资产，以及预期收益、波动率和协方差。用户可以调整风险权重、持仓数量、单行业上限和防御资产下限。

`PortfolioCase` 构造 `QUBOProblemIR`：收益项降低 energy，协方差表示组合风险，持仓、行业和防御资产约束展开为罚项。该结构包含稠密和带符号耦合，因此默认使用 Digital。

业务结果显示预期收益、波动率、入选资产和逐项约束。量子实验显示参数化通用门线路、QAOA 逻辑层、参数点目标值和 counts。

### 交易结算

默认数据包含 10 条三币种结算指令。每条指令记录名义金额、优先级、现金单位、依赖和冲突。用户可以调整金额权重、优先级权重、批次上限和罚项倍数。

同一份 `QUBOProblemIR` 同时用于 Digital 和 Hybrid。交易冲突使用完整参考坐标进入 Problem mapping；`FinanceModeAdvisor` 只有在整个 core 冲突组完整映射、物理 interaction 图没有漏边或补边、且 Digital residual 非空时才推荐 Hybrid。金额、优先级、币种额度、依赖和批次限制保留为 Digital residual。

业务结果显示结算金额、交易数量、流动性占用、约束和未选原因。量子实验显示 D-A-D block 顺序、原子排列、合并控制波形、数字 residual 线路和末端 counts。

### 反欺诈调查编排

默认数据包含 12 条已经由上游系统生成的告警。输入包括风险分、涉及金额、时效、关键实体和预计工时。本场景只安排调查任务，不判断交易是否欺诈。

共享实体冲突使用完整参考坐标进入 Problem mapping。`FinanceModeAdvisor` 逐条检查三条 core 冲突、实际物理 interaction、漏边、补边和异常 Analog 二体项；全部通过时由 Analog 表达冲突，Digital 保留风险、金额、时效、席位和资源约束。用户把单实体并行上限改为 2 后，冲突项可能消失，模式建议会随新 Problem 重新计算。

业务结果显示风险覆盖、金额覆盖、调查任务、工时和未选原因。页面持续说明结果是调查编排，不是欺诈识别。

### 抵押品分配

默认数据包含 8 个“抵押品批次到保证金需求”的候选分配。三个需求分别要求一个候选；同一抵押品批次不能重复使用。每个候选记录抵押品价值、融资成本、资源单位和折扣说明。

资格、需求覆盖和批次唯一性属于全局与二部匹配约束，默认使用 Digital。业务结果显示三个需求的分配、总价值、成本、资源使用和未分配原因。

### 日内流动性调度

默认数据包含 8 个融资、划拨和换汇动作，覆盖 CNY、USD 和 HKD。动作记录时点、渠道、覆盖单位、成本、冲突和前置依赖。用户可以调整选择数量、最低覆盖、单币种上限和价值/成本权重。

时间顺序、依赖和币种约束不适合用无向几何相互作用直接表达，因此默认使用 Digital。业务结果显示入选动作、总覆盖、总成本、分组数量和约束。

### 企业授信额度配置

默认数据包含 8 个已经准入的额度档位。每项记录行业、风险调整价值、成本、资本单位和违约概率说明。用户可以调整配置数量、资本上限、行业上限和价值/成本权重。

资本和行业集中度是全局资源约束，默认使用 Digital。该场景不判断企业能否获得授信，页面持续显示“不用于授信审批”。

### 衍生品定价与风险情景

定价输入包括产品、标的价格、执行价、波动率、利率、期限、障碍价和 Monte Carlo 路径数。

- 欧式看涨和看跌使用 Black-Scholes，并用 256 步二叉树交叉检查。
- 亚式和上敲出障碍期权使用固定 seed Monte Carlo。
- Delta、Gamma 和 Vega 使用确定性有限差分计算。
- Monte Carlo 产品返回标准误差；障碍期权另返回敲出概率。

量子实验是一个独立的风险情景选择 Problem。标的价格冲击和波动率冲击组成 `3 x 3` 格点，相邻情景视为信息接近的冲突节点。带二维位置的 `GraphProblemIR` 可以完整编译为 Analog QAA/AHS。

经典价格不会读取量子执行结果。`DerivativePricingResult` 没有 counts，`ProblemExecutionResult` 没有 `reference_price`。页面和报告均说明 counts 不参与定价。

## 工作台

公开工作台由 React + TypeScript 实现，通过 FastAPI 读取分析和执行结果。桌面端使用三栏布局：

```text
顶部：产品名 | 本地模拟 | 合成数据 | 无真实硬件

场景导航 | 业务与执行参数 | 结果页签
```

左侧显示七个场景及默认推荐模式。控制区包含预设、场景业务参数、执行模式、shots 和 seed。场景目录同时返回经过默认输入验收的执行配置；切换场景或预设时自动加载，手动修改后显示“自定义执行配置”。Digital 还提供 `p=1~3`、参数搜索方式和评估预算；Hybrid 与 Analog 隐藏不适用的 QAOA 控件。模式分段控件禁用不适用的模式，具体原因保留在 Problem 映射页。

同一业务输入下，各执行模式保存独立结果。只有业务输入、shots、seed、层数、搜索方式和评估预算完全一致时才会恢复原结果。修改任一参数后，旧的业务结果、counts、term mapping、量子程序和审计内容立即清空，避免把不同运行混在同一页面。

业务参数变化时，工作台会立即重新构造并分析 Problem，同步更新模式选项、推荐标识、资源估算、系数结构和原子布局。只修改 shots、seed 或参数搜索配置时，Problem 分析保持不变，只使原运行结果失效。例如把调查场景的单实体并行上限从 1 改为 2 后，共享实体冲突消失，推荐模式会从 Hybrid 切换为 Digital。

五个页签的职责固定：

1. 业务结果：业务候选散点、当前方案和未选原因。
2. 场景态势：当前预设对应的合成输入、候选空间、冲突图或依赖结构。
3. Problem 映射：资源估算、三模式判断、QUBO/图结构、参数点目标值和逐项 term mapping。
4. 量子实验：原生程序、原子排列、控制波形和 counts。
5. 审计证据：hash、Target、Backend、seed、shots、耗时、报告路径和执行边界。

### Digital 视图

通用门线路从实际 `CircuitIR` 读取 H、RZ、RX、CX 和 measurement。深度窗口避免长线路被压缩到不可读；图高度按 qubit 数计算。用户可以切换到 U1、U2、RX1 的 QAOA 逻辑层表示。线路和 counts 上下排列。

### Hybrid 视图

页面从实际 `HybridProgram` 读取 Digital、Analog 和 measurement block。原子排列来自 Problem mapping layout；Rabi、Detuning 和 Phase 在一张共享时间轴图中展示。local detuning 存在时，波形图显示实际局域控制中的最大绝对幅值，而不是只显示为零的 global detuning。

### Analog 视图

页面不显示数字线路。原子阵列与波形并列，x、y 使用相同比例；counts 位于下方。窄屏下两张图改为上下排列。

## 运行状态

FastAPI 使用线程池执行本地量子模拟。点击运行后按钮立即禁用，完成或失败后恢复。每次运行重新执行以下步骤：

```text
输入校验
  -> FinanceProblemDefinition
  -> ProblemCompiler.analyze()
  -> FinanceModeAdvisor
  -> ProblemCompiler.compile()
  -> compiled.optimize(parameter_sets=...)
  -> ProblemExecutionResult
  -> 业务解码与约束复核
  -> 页面和标准 HTML 报告
```

Hybrid 和 Analog 使用 `complex128`。12-site 调查 Hybrid 在 `complex64` 下会积累足以触发归一化检查的误差，因此 Demo 不使用该精度。

前端提交任务时会记录完整运行签名。任务完成后，如果用户已经修改输入或切换模式，结果只写入对应签名缓存，不覆盖当前页面。

## 结果解释

- `best_observed_candidate` 是已采样候选中目标值最低的一项。
- 最常见 bitstring 与最佳观测候选可能不同。
- `baseline_solution` 是小规模确定性枚举基准。
- 候选不可行时，页面可以把 baseline 作为业务展示方案，但同时保留原候选和展示来源。
- 当前七个默认场景和全部 21 个标准预设均能用推荐配置得到 `best_observed` 可行候选。“日终压力”和“行业集中压降”因浅层固定参数未能采到可行候选，已从标准预设删除，不以 `classical_baseline` 伪装成量子结果。
- `optimize(parameter_sets=...)` 只比较传入的离散参数点。Digital 可由预设、二维网格或固定 seed 采样生成最多 24 个点，但仍不属于连续优化。
- counts 柱状图显示前 10 个状态，其余状态合并为“其他状态”，总数仍等于 shots。

## 交付边界

- 不连接真实行情、交易、托管、支付、反欺诈或授信系统。
- 不提交真实量子硬件或云端任务。
- 不实现 QAE、生产估值、校准、通用图嵌入或量子优势验证。
- 不把经典 baseline、固定预设或页面动画写成量子结果。
- 结果不构成金融建议或自动决策。

## 验证

Python 单元和集成测试覆盖 QUBO 展开、业务约束、模式建议、经典定价、风险格点和七场景执行。前端测试覆盖模式切换、不可用模式、运行状态和线路高度，TypeScript 与生产构建也作为门禁。

页面验收还需检查三种视口：

- `1440 x 900`
- `1280 x 720`
- `390 x 844`

每种视口检查页面级横向溢出、控件重叠、canvas 非空、线路高度、原子比例、波形和 counts。
