# CASCAQit 金融量子实验台技术讲解手册

这份手册写给准备演示系统的软件工程师。读者不需要金融工程或量子计算背景，但需要理解普通的软件分层、编译流程、数据模型和测试。文章以当前代码为准，解释 Demo 为什么这样建模、三种量子链路分别做什么、页面上的图表如何阅读，以及哪些结论不能从这次演示推出。

## 先记住四个结论

第一，这不是把七个金融场景强行包装成量子计算。系统先把业务目标和约束写成统一数学问题，再根据问题结构选择 Digital、Hybrid、Analog 或经典算法。

第二，Demo 展示的是从业务建模到量子程序、采样结果和业务解码的完整软件链路。当前运行使用 `LocalBackend` 本地模拟器，不是真实量子硬件，也没有证明量子加速或量子优势。

第三，中性原子的主要价值体现在问题表达方式上。原子位置和 Rydberg 相互作用适合表示局域排斥关系；全局约束、方向依赖和带符号的稠密耦合仍适合用数字门处理。Hybrid 的意义是让两类结构各用合适的方式表达，不是为了让页面同时出现线路和波形。

第四，页面上的业务结果不会直接信任量子位串。系统会按原始业务输入重新计算收益、成本、容量、依赖和冲突，只有复核通过后才把候选标为可行。

可以用下面一句话介绍产品：

> CASCAQit 金融量子实验台把金融目标和约束统一建模为 QUBO、Ising 或图问题，由编译器按问题结构生成 Digital、Analog 或 Hybrid 中性原子程序，再把采样位串还原为可复核的业务方案。

## 用软件编译器理解这套系统

这套 Demo 最容易从编译器视角理解。它与普通编译系统的对应关系如下：

| 普通软件编译 | 金融量子 Demo |
|---|---|
| 业务源代码 | 资产、交易、告警、融资动作等业务输入 |
| 语义检查 | `scenario.validate()` |
| 中间表示 | `QUBOProblemIR`、`GraphProblemIR`、`IsingModelIR` |
| 编译分析 | `ProblemCompiler.analyze()` |
| 目标相关 Lowering | Digital、Hybrid 或 Analog 编译 |
| 可执行程序 | `Circuit`、`HybridProgram`、`AHSProgram` |
| Runtime | `LocalBackend` |
| 程序输出 | bitstring、counts、能量和参数历史 |
| 结果解释 | 场景 `decode()` 与业务约束复核 |
| 调试证据 | Problem、analysis、compile、execution hash |

完整流程是：

```text
业务输入
  -> 输入校验
  -> FinanceProblemDefinition
  -> Canonical Problem 和逻辑 Hamiltonian
  -> Target-aware mapping
  -> Digital / Hybrid / Analog 编译
  -> 参数绑定和本地模拟
  -> counts 与候选位串
  -> 业务解码和约束复核
  -> React 页面与标准 HTML 报告
```

`Unified Problem API` 的关键不是减少几个函数调用，而是让三种模式共用同一份问题定义、逻辑变量顺序、Hamiltonian、解码器和执行结果结构。它类似数据库查询优化器：用户描述“要解决什么问题”，编译器根据 Target（目标机）能力决定“怎样生成程序”，而不是要求每个金融开发者手写量子线路和控制波形。

## 理解金融建模所需的最少知识

### 优化问题和定价问题不是一回事

Demo 中六个场景属于组合优化：投资组合、交易结算、反欺诈调查编排、抵押品分配、日内流动性调度和授信额度配置。它们都在有限候选中选择一个子集，同时满足业务约束。

衍生品场景包含两项独立任务：

- 价格和 Greeks 由经典金融模型计算；
- 量子图问题选择有代表性的风险冲击情景。

因此不能说“七个场景都由量子计算解决”，也不能说“量子 counts 得出了期权价格”。

### 目标函数、约束和可行解

一个业务优化问题通常包含三部分：

- 决策变量：选择哪些资产、交易、告警或动作；
- 目标函数：希望收益更高、成本更低、覆盖更多或结算金额更大；
- 约束：持仓数量、流动性、资本、冲突、依赖和行业集中度。

满足全部约束的候选叫可行解。可行解之间再比较目标值。低能量只说明一个位串对 QUBO 目标较好，不自动说明它满足原始业务规则，所以每个场景都实现了独立业务解码。

### QUBO 是怎样建出来的

QUBO 的全称是 Quadratic Unconstrained Binary Optimization（二次无约束二元优化）。每个变量只能取 0 或 1：

```text
x_i = 1  表示选择第 i 个业务对象
x_i = 0  表示不选择
```

能量函数写成：

```text
E(x) = offset + sum(a_i * x_i) + sum(b_ij * x_i * x_j)
```

求解器寻找能量较低的位串。为了最大化业务价值，代码通常把价值写成负线性系数：

```text
E_value = -sum(value_i * x_i)
```

这样选择高价值对象会降低能量。成本和风险通常写成正项，选择后会提高能量。

“无约束”不等于没有业务约束。约束会被转换成能量罚项。例如恰好选择 `K` 项：

```text
P * (sum(x_i) - K)^2
```

只有选择数量等于 `K` 时罚项为零。`P` 必须足够大，否则求解器可能宁愿违反约束来获取更多业务收益。Demo 先计算无约束目标所有系数的绝对值和，再据此确定罚项尺度。

两类常见关系可以直接写成二次项：

```text
冲突：P * x_i * x_j
依赖：P * x_child * (1 - x_parent)
```

冲突双方同时入选时才受罚。依赖项只在选择子项却没有选择前置项时受罚。

容量上限需要 slack（松弛变量）。例如使用量不能超过 `C`：

```text
used + slack = C
```

Demo 使用有界二进制权重表示 `slack`，避免辅助位表示出业务上不存在的容量。下限约束则写成：

```text
used - slack = minimum
```

业务变量会解码为资产、交易或动作；slack 只服务于约束，不应在页面上被解释成业务对象。

### QUBO、Ising 和 Hamiltonian 的关系

QUBO 使用 0/1 变量。量子程序通常使用 Pauli-Z 算符表示计算基状态。编译器通过 0/1 与 Z 本征值之间的代换，把 QUBO 线性项和二次项转换成 Z、ZZ Hamiltonian 项。

可以把 Hamiltonian 理解为量子版本的目标函数：不同量子态对应不同能量，算法通过参数化演化让低能量状态获得更高的测量概率。这里的“能量”是数学目标值，不是金融金额。

### 经典基线为什么仍然存在

当前问题规模较小，Demo 会枚举业务变量形成经典基线。它有三个用途：

- 检查输入是否存在可行解；
- 对照量子采样候选；
- 采样候选不可行时，给页面提供明确标记的可行参考方案。

经典基线不会被伪装成量子结果。结果对象分别保留 `business_candidate`、`baseline_solution` 和 `displayed_solution`。如果页面回退到基线，审计信息会记录展示来源。

## 理解量子实验所需的最少知识

### qubit、bitstring 和 counts

经典 bit 只能是 0 或 1。qubit 在测量前可以处于多个计算基状态的叠加。一次测量仍只得到一个普通位串，例如 `010110`。

同一个参数化程序执行多次测量，每个状态出现的次数组成 counts：

```text
010110: 18
110010: 11
010010: 7
...
```

`shots` 是测量次数，所有 counts 之和应等于 shots。counts 表示采样分布，不是概率证明，也不是金融金额。最常见位串不一定是目标值最低的位串；系统会在已经观测到的候选中计算目标值，选出 `best_observed_candidate`。

### Digital QAOA 做什么

QAOA 是 Quantum Approximate Optimization Algorithm（量子近似优化算法）。当前 Digital 路径使用一层或编译器支持的参数化结构：

```text
H 初始化
  -> cost Hamiltonian 演化，参数 gamma
  -> mixer 演化，参数 beta
  -> 测量
```

H 门把每个量子位放入均匀叠加。cost 演化把 QUBO 的 Z/ZZ 项编码为相位；mixer 使用 RX 旋转，让不同候选状态继续发生混合。程序最终测量得到位串分布。

实际通用门线路中：

- 单个 Z 项使用 `RZ`；
- 两变量 ZZ 项使用 `CX -> RZ -> CX`；
- mixer 使用 `RX`；
- `M` 表示测量。

页面中的 `U1`、`U2`、`RX1` 是 QAOA 逻辑层摘要，不是新的通用门名称。客户询问具体执行了什么门时，应切换到“通用门”视图，以 H、RZ、CX、RX 和测量为准。

Demo 默认只比较两个固定参数点。它不是连续参数优化器，也不能据此声称找到了全局最优参数或全局最优业务方案。

### 中性原子的 Analog AHS 做什么

AHS 是 Analog Hamiltonian Simulation（模拟哈密顿量演化）。中性原子平台把原子放在二维位置上，并用激光控制它们的量子态。处于 Rydberg 激发态的原子之间会产生与距离相关的相互作用。

这类物理结构适合表达图问题：

- 一个业务变量对应一个原子 site；
- 原子位置对应图的几何布局；
- 足够近的原子之间形成强相互作用；
- 相互冲突的两个节点不容易同时处于选中状态。

页面显示三种主要控制量：

- Rabi：驱动基态与 Rydberg 态转换的强度；
- Detuning：调整某个状态相对能量的偏置，可为全局或局域控制；
- Phase：驱动相位，决定旋转方向；当前协议中通常为常量零。

完整 Analog QAA 使用三段线性控制：Rabi 从零升高、保持、再降回零；Detuning 从初始负值变化到目标 Hamiltonian 所需的终值。风险情景场景会看到这种有变化的波形。

### Hybrid D-A-D 做什么

Hybrid 使用 Digital-Analog-Digital（D-A-D）拓扑，算法仍是 QAOA，不是名为 DAD 的新算法：

```text
Digital：H 门准备均匀叠加
  -> Analog：执行可映射的 cost Hamiltonian
  -> Digital：补齐 residual cost，并执行 RX mixer
  -> measurement
```

Analog 部分只承担当前几何和 Target 能表达的贡献。其余逻辑系数由 Digital residual（数字剩余项）补齐。编译器检查 Analog contribution 与 Digital residual 相加后仍等于原逻辑 Hamiltonian，不能为了展示 Hybrid 随意删除或增加业务系数。

当前 Hybrid Analog block 是固定 cost 演化：Rabi 为零，Detuning 和 Phase 可以是常量。因此波形较平可能是协议本身的事实，不一定是图表故障。完整 Analog QAA 才使用随时间变化的 Rabi 和 Detuning 退火曲线。

当前编译器只支持一层 D-A-D，不包含通用多层 Hybrid、非对易 Trotter 分解、自动图嵌入或生产硬件调度。

### 本地模拟器意味着什么

`LocalBackend` 对生成的数字、模拟或混合程序进行本地数值计算。默认设置固定 seed，结果可重复；Hybrid 和 Analog 使用 `complex128`，减少状态交接和时间演化中的数值误差。

状态向量规模按 `2^n` 增长。默认场景中最大的 16 个逻辑变量对应 65,536 维状态向量，所以当前本地演示规模不能直接外推到生产问题，更不能代表真实中性原子设备的原子数和性能。

本地模拟能验证建模、编译、程序结构、状态演化、counts、解码和报告链路，但不能验证真实硬件噪声、校准、排队、保真度或运行速度。

## Unified Problem API 的建模和编译原则

### 金融语义与数学问题分层保存

CASCAQit 的 Problem IR 保存可编译的数学结构，金融 Demo 的 `FinanceProblemDefinition` 额外保存：

- `business_variables`：可以解码回资产、交易或告警的变量；
- `auxiliary_variables`：slack 等辅助变量；
- `term_groups`：目标、业务冲突、全局约束、依赖和辅助罚项；
- `preferred_mode`：场景设计上的首选模式。

`term_groups` 不修改 QUBO 系数。它保留“这条项来自什么业务规则”的解释，供模式选择和页面展示使用。

### analyze 和 compile 分工

`ProblemCompiler.analyze()` 不执行程序。它生成：

- Canonical Problem；
- 逻辑 Hamiltonian；
- 变量顺序和原子布局；
- 每个 term 的候选实现方式；
- 三种模式的可行性诊断；
- 资源估算。

`compile()` 接受明确的 mode、algorithm 和 Target：

| mode | algorithm | 产物 | 当前规则 |
|---|---|---|---|
| `digital` | `qaoa` | `Circuit` | 全部逻辑项由通用门表达 |
| `hybrid` | `qaoa` | `HybridProgram` | 一层 D-A-D，Analog 与 Digital contribution 都非空 |
| `analog` | `qaa` | `AHSProgram` | 完整 Hamiltonian 必须由 AHS 表达，不能隐藏数字项 |

三种模式共享 logical order（逻辑变量顺序）。这点很重要：相同位置的 bit 在不同模式下仍代表同一个业务变量，模式对比才有意义。

### 当前 FinanceModeAdvisor 怎样推荐模式

模式判断同时查看两类证据：

- 编译器证据：目标机能否实现、哪些 term 进入 Analog、哪些保留为 Digital；
- 金融证据：场景是否把某对变量明确标记为业务冲突。

当前实现的主要规则是：

- 稠密目标、全局约束或方向依赖占主导时，优先 Digital；
- 编译器能完整表达全部 Hamiltonian，且业务冲突图完整进入 Analog 时，选择 Analog；
- 至少有一条可追溯业务冲突进入 Analog，同时 Digital residual 非空时，允许 Hybrid；
- 缺少真实 Analog 业务项时，不为展示效果制造 Hybrid。

这里有一个需要向客户谨慎说明的限制。当前交易结算默认声明三条业务冲突，确定性布局只匹配到其中一条，但现有顾问仍会推荐 Hybrid。架构设计中的下一步门禁更严格：要求完整业务冲突组覆盖、拒绝无业务来源的 Analog term，并验证几何没有漏边或补边。这些规则尚未在当前 Demo 中全部实现。

因此当前交易结算 Hybrid 可以证明 D-A-D 编译和执行链路已经工作，也可以证明至少一条真实交易冲突进入了 Analog；它不能证明全部结算冲突都由原子几何完整承担。反欺诈默认输入声明的三条共享实体冲突当前都能匹配。

## 七个场景逐一讲解

下面的规模来自当前默认输入和当前编译器分析。业务变量是客户能理解的对象；逻辑变量还包括 slack 等辅助位。

| 场景 | 业务变量 | 逻辑变量 | 逻辑 term | 状态向量维度 | 当前推荐 |
|---|---:|---:|---:|---:|---|
| 多资产投资组合 | 8 | 12 | 56 | 4,096 | Digital |
| 交易结算 | 10 | 16 | 52 | 65,536 | Hybrid |
| 反欺诈调查编排 | 12 | 12 | 78 | 4,096 | Hybrid |
| 抵押品分配 | 8 | 8 | 17 | 256 | Digital |
| 日内流动性调度 | 8 | 16 | 96 | 65,536 | Digital |
| 企业授信额度配置 | 8 | 14 | 87 | 16,384 | Digital |
| 衍生品风险情景 | 9 | 9 | 21 | 512 | Analog |

### 多资产投资组合：为什么用 Digital

业务问题是从八类合成资产中选择固定数量，并按等权重持有。输入包含预期收益、波动率、协方差、行业、防御属性、风险权重和持仓约束。

每个资产对应 `x_i`。如果选择 `K` 项，目标为：

```text
risk_weight * x.T @ normalized_covariance @ x / K^2
- (1 - risk_weight) * normalized_return.T @ x / K
```

风险项为正，收益项为负。约束包括：

- 恰好选择 `K` 项；
- 单行业不超过上限；
- 防御资产不少于下限。

协方差矩阵会形成稠密、带正负符号的两两耦合，行业和防御要求又是全局约束。这些结构不等同于少量局域排斥边，所以 Digital QAOA 能更直接地保留完整问题。

演示时先看风险收益散点和入选资产，再进入 Problem 映射看协方差如何变成 ZZ 项，最后看通用门线路和 counts。可以强调“同一份市场输入经过建模、编译、采样和业务复核”，不要说“量子算法已经优于经典投资组合优化”。

当前限制是等权重选择，不做连续仓位优化；市场数据全部为合成数据，也没有交易成本、换手率、税费或监管规则。

### 交易结算：Hybrid 在哪里参与

业务问题是从十条三币种指令中选择本批次结算的交易。每条指令包含名义金额、优先级、离散现金单位、前置依赖和冲突。

每条交易对应一个业务变量。金额和优先级各自归一化后加权形成交易价值，QUBO 使用负线性系数最大化总价值。约束包括：

- 每个币种的流动性桶上限；
- 批次交易数上限；
- 选择子交易时必须选择前置交易；
- 冲突交易不能同时选择。

Hybrid 的 Analog 中段承载可映射的交易冲突；金额、优先级、依赖、流动性和批次限制保留为 Digital residual。页面中的 D-A-D block、原子阵列、控制波形和数字 residual 都来自实际 `HybridProgram`，不是前端画出的示意动画。

默认模型声明三条交易冲突，当前布局只把其中一条识别为可追溯 Analog 业务对。演示时可以说“当前链路已经让真实交易冲突参与 Analog 演化”，不能说“三条冲突都已经原生映射”或“完整结算 QUBO 已全部由 Analog 求解”。

`cash_units` 是演示用整数资金桶，不是交易名义金额。这个场景只选择结算批次，不执行清算账务、支付报文或资金交割。

### 反欺诈调查编排：为什么比结算更适合作为 Hybrid 主场景

输入是上游系统已经生成的十二条告警，包括风险分、涉及金额、等待时长、关键实体和预计调查工时。本场景不识别欺诈，只安排有限调查席位。

风险、敞口和时效先分别归一化到 0..1，再按用户权重加权。约束要求固定数量的调查席位全部分配，并限制同一实体同时进入调查队列的告警数。

当单实体并行上限为 1 时，同一实体的告警形成明确冲突边。默认输入中有三条这类共享实体冲突，当前三条都能与 Analog interaction 对应；调查价值和席位约束保留为 Digital。因此该场景比当前结算场景更适合说明 Hybrid 的业务含义。

把单实体并行上限改为 2 后，冲突边消失，系统会重新建模并把推荐模式切换到 Digital。这是很好的现场演示点：它证明模式不是写死在页面里，而是随着业务输入变化。

业务结果中的风险覆盖、敞口覆盖和时效覆盖只是入选告警占输入总量的比例。它们不表示欺诈识别准确率、召回率或案件损失减少。

### 抵押品分配：为什么仍然是 Digital

每个候选项表示“某一抵押品批次分配给某个保证金需求”的方案。默认数据覆盖 CCP 和两个双边需求。

目标在抵押品价值与融资成本之间权衡。三个需求各要求一个方案，同一抵押品批次不能重复使用。虽然存在两条候选互斥关系，但完整问题主要是分组精确数量和分配约束，少量冲突边不足以代表整个业务模型，所以默认使用 Digital。

Demo 不读取真实持仓、资格规则、折扣表或法律协议。页面上的 HQLA、haircut 和融资成本是合成说明字段，不应被解释为真实抵押品管理建议。

### 日内流动性调度：方向依赖为什么适合 Digital

候选项是八个融资、内部划拨或外汇掉期动作，标签带有时点和币种。默认模型要求选择四项、获得至少十二个离散流动性单位、每个币种最多两项，并包含一条冲突和一条前置依赖。

依赖是有方向的：续作动作需要前序动作。Rydberg 相互作用天然表示无向的两两排斥，不直接表示“先有 A 才能有 B”，所以这类结构更适合数字门。

需要注意，当前实现没有构建完整的分时现金余额递推，也没有模拟支付队列。时点主要存在于候选标签和业务说明中，模型实际计算的是动作子集、覆盖单位、分组、冲突和依赖。

### 企业授信额度配置：这不是自动授信审批

输入是八个已经准入的额度候选。每项包含行业、风险调整价值、成本、离散资本单位和违约概率说明。

模型选择固定数量的候选，限制总资本单位和单行业数量，并包含一对业务定义的互斥候选。资本预算和行业集中度是全局约束，所以默认使用 Digital。

这个场景没有客户画像、财务报表、评级模型、监管资本计算或审批流程。它只能演示“对已准入候选做额度组合配置”，不能说系统在判断企业是否应获得贷款。

### 衍生品：经典定价和 Analog 情景选择必须分开讲

经典链路支持四类产品：

- 欧式看涨和看跌：Black-Scholes 主价格，256 步二叉树交叉检查；
- 亚式看涨：固定 seed Monte Carlo；
- 向上敲出看涨：固定 seed Monte Carlo，并返回敲出概率。

Delta、Gamma 和 Vega 由中心有限差分计算。Monte Carlo 路径服从风险中性几何布朗运动，结果还包含标准误。实现没有波动率曲面、利率曲线、分红、交易日历或市场校准，只是确定性演示定价器。

量子链路使用固定 3×3 风险网格。横轴是标的价格冲击 `-12% / 0 / +12%`，纵轴是波动率冲击 `-8% / 0 / +8%`。上下左右相邻的情景视为信息接近，图问题选择互不相邻的代表节点，相当于最大独立集实验。

九个图节点有明确二维位置，完整 Hamiltonian 可以由当前 AHS 目标表达，所以推荐 Analog QAA。页面会显示 3×3 原子排列、Rabi/Detuning/Phase 波形和 counts。

当前风险图对四类产品都相同，量子选择没有读取经典价格或 Greeks。正确说法是“经典模型负责定价，Analog 负责独立的风险情景压缩实验”；不能说“量子计算提升了定价精度”或“counts 参与了价格计算”。

## 页面五个页签怎样讲

### 业务结果

先回答客户最关心的问题：选了什么、核心指标是多少、约束是否满足、为什么某些候选没有入选。这里展示的是业务解码结果，不是裸量子位串。

如果采样候选不可行而页面展示经典基线，需要直接说明展示来源。不可把回退后的可行方案说成量子采样命中的方案。

### 场景态势

这个页签展示当前合成输入和业务关系，例如风险收益散点、交易依赖、共享实体网络或风险网格。它帮助客户先理解业务问题，再看数学和量子映射。

### Problem 映射

这里是技术演示的核心证据：

- Canonical Problem 表示编译器实际收到的问题；
- QUBO/图结构显示线性项和二次项；
- term groups 保留业务来源；
- 模式表说明 Digital、Hybrid、Analog 的编译可行性和业务适配判断；
- resource estimate 显示逻辑变量、term、线路估算和状态向量维度；
- term mapping 显示逻辑系数分别由 Analog 和 Digital 承担多少。

`Resource usage` 是编译估算，不是真实硬件资源账单或性能测试结果。

### 量子实验

Digital 页面显示通用门线路、QAOA 逻辑层、参数点目标值和 counts。

Hybrid 页面显示 D-A-D block、原子排列、控制波形、Digital residual、参数历史和末端 counts。Analog 中段与前后数字块在同一次模拟状态中连续执行，不是三个互不相关的图片。

Analog 页面不显示数字线路，只显示原子阵列、AHS 控制和 counts。原子图 x、y 使用相同比例，避免几何关系被视觉拉伸。

波形图对每条曲线单独归一化以便同图观察，同时保留原始值。曲线形状来自 Native Program；前端不会为了演示效果伪造脉冲。

### 审计证据

Problem、analysis、compile 和 execution hash 把一次运行的主要阶段串起来。页面还显示 Target、Backend、seed、shots、耗时以及是否访问硬件、云端和网络。

这些字段的价值类似软件供应链和可观测性：客户可以确认当前页面来自哪一次输入、哪种模式和哪次执行，避免把旧 counts 或旧波形混入新参数结果。

## 这套 Demo 真正可以强调的价值

### 从业务问题自动生成原生程序

用户不需要为每个场景手写 H、RZ、CX、RX 门，也不需要手工拼接原子寄存器和控制波形。统一 Problem 经分析后生成 `Circuit`、`HybridProgram` 或 `AHSProgram`。这比固定线路动画更接近一个量子软件开发平台。

### 同一问题可以比较三种表达方式

Digital、Hybrid 和 Analog 共用问题 hash、逻辑变量顺序、Hamiltonian 和 decoder。对照实验比较的是同一个业务问题的不同程序形式，而不是三套各自调过结果的示例。

### 中性原子几何承担可解释的业务关系

在反欺诈和部分结算模型中，原子 interaction 可以追溯到共享实体或交易冲突；衍生品风险网格的节点位置也来自明确二维情景。这比“任意 QUBO 都声称适合 Analog”更克制。

### 业务语义没有在编译后丢失

变量名、term group、bitstring 顺序和解码器贯穿整个链路。用户可以从一个 counts 状态回到具体资产、交易、告警或动作，并重新检查约束。

### 展示内容来自实际分析和执行对象

数字线路读取 `CircuitIR`，原子和波形读取 AHS/Hybrid Native Program，counts 读取执行结果，参数历史读取每个参数点评估。前端主要做格式转换和绘图，不自行编造量子程序。

### 离线确定性适合客户演示和研发验证

固定 seed、合成输入和本地执行降低网络、账号、云排队和外部数据变化对演示的影响。相同输入可以复现，并通过 hash 和报告核对。这个优势属于软件交付和可审计性，不是量子性能优势。

## 中性原子的潜力应怎样表达

可以说：

- 中性原子支持可重构二维排列，适合研究图结构和组合优化的物理映射；
- Rydberg 相互作用能原生表达一定范围内的排斥关系；
- AHS 允许直接控制 Rabi、Detuning 和 Phase，减少部分问题对长数字门分解的依赖；
- D-A-D 让局域相互作用与通用门在同一程序中组合，为复杂业务约束保留数字表达。

不能说：

- 当前 Demo 已经在真实中性原子硬件运行；
- 当前问题比经典算法更快、更准或更省成本；
- 原子数可以直接扩大到生产规模而无需重新验证布局、校准和误差；
- 任意金融 QUBO 都适合 Analog 或 Hybrid；
- counts 的最高柱就是全局最优解。

专业演示的可信度来自边界清楚。客户通常能接受“这是完整软件链和物理映射验证”，但不能接受把本地模拟器包装成真机结果。

## 建议的 20 分钟演示顺序

### 1. 开场定位，2 分钟

可以这样说：

> 今天展示的不是一条固定量子线路，而是从金融业务输入开始，经过统一建模、目标机分析、模式选择、程序生成、执行、业务解码和审计的完整流程。当前使用本地模拟器，重点验证软件链路和中性原子问题表达，不宣称量子优势。

打开七场景列表，说明系统不会把所有问题都强行选择 Hybrid。

### 2. 投资组合 Digital，4 分钟

操作：选择投资组合，修改风险权重，观察模式分析和业务结果变化，再运行。

讲解重点：

- 资产选择如何变成二元变量；
- 收益是负能量项，协方差风险是二次项；
- 持仓、行业和防御资产约束如何成为罚项；
- 稠密协方差和全局约束为什么选择 Digital；
- 通用门线路来自实际 QAOA 编译。

不要花时间逐个解释全部门。客户理解 H、cost、mixer、measurement 四段就足够。

### 3. 反欺诈 Hybrid，6 分钟

操作：先用单实体并行上限 1 运行 Hybrid，展示共享实体网络、D-A-D、原子、波形、residual 和 counts；再把并行上限改为 2，观察推荐模式回到 Digital。

讲解重点：

- Analog 表达共享实体冲突；
- Digital 保留风险权重和席位约束；
- 业务输入变化会重建 Problem 和模式建议；
- 结果是调查资源编排，不是欺诈识别。

这一段最能说明 Unified Problem API 和 Hybrid 不是前端写死的。

### 4. 衍生品 Analog，5 分钟

操作：切换欧式或障碍期权，先看经典价格和 Greeks，再看独立的 3×3 Analog 风险情景实验。

讲解重点：

- 成熟经典模型继续负责它擅长的定价；
- 量子图问题只负责代表性情景选择；
- 原子二维排列直接对应风险网格；
- QAA 波形比 Hybrid cost block 更有动态变化；
- counts 不进入价格计算。

### 5. 审计收尾，3 分钟

展示 hash、Backend、seed、shots 和无硬件/云端访问字段。最后说明真实客户试点还需要接入业务数据、选择有价值的问题规模、建立经典基准，并在真实 Target 和校准数据上重新验证。

## 客户常见问题

### 这是在真实量子计算机上运行吗？

不是。当前使用 CASCAQit `LocalBackend` 本地模拟执行生成的 Digital、Analog 和 Hybrid 原生程序。页面审计字段明确记录 `hardware_execution=false`、`cloud_execution=false` 和 `network_accessed=false`。

### 既然有经典枚举，为什么还需要量子实验？

当前小规模枚举用于校验建模和结果，不是产品最终求解方案。量子实验验证的是统一建模、三模式编译、中性原子映射和业务解码链路。是否在更大规模或真实硬件上获得实际收益，需要与成熟经典算法做单独基准测试。

### counts 最高的状态就是最优方案吗？

不一定。最高频状态只是最常被采样的状态。系统会计算已观测状态的目标值，并选择能量最低的 `best_observed_candidate`；随后还要重新检查业务约束。

### 为什么有些场景不用 Hybrid？

Hybrid 只有在 Analog 中段承载真实局域业务结构，并且 Digital residual 也有必要时才合理。稠密协方差、全局容量和有向依赖通常更适合 Digital；完整图能由 AHS 表达时直接用 Analog，不需要人为增加 Digital block。

### 为什么 Hybrid 波形看起来是平的？

当前 Hybrid 中段执行固定 cost Hamiltonian，Rabi 为零，Detuning 和 Phase 可以保持常量，所以平坦波形符合当前协议。Analog QAA 使用三段退火控制，Rabi 和 Detuning 会随时间变化。判断是否异常应查看原始波形数值和 Native Program，不能只看视觉起伏。

### 这个 Demo 的量子优势是什么？

当前 Demo 没有验证量子优势。已经验证的是：金融问题可以统一建模，编译器能生成三种原生程序，中性原子相互作用能承担部分可追溯冲突，结果可以解码和审计。性能优势必须在真实问题、强经典基线和目标硬件上测量。

### 能接入客户真实数据吗？

架构上可以把合成 dataclass 输入替换为经过权限、脱敏和校验的业务数据适配器，但当前版本没有行情、核心交易、托管、支付、反欺诈或授信系统连接器。接入真实数据还需要统一字段口径、约束来源、合规审查和结果责任边界。

### 代码由 AI 辅助生成，运行时是否也依赖 AI？

不依赖。运行时没有调用大语言模型。业务目标、QUBO 系数、经典定价、量子编译和本地模拟都由明确代码和固定数学规则执行，并由测试、seed、hash 和报告复核。AI 辅助开发不等于结果由生成式 AI 临时生成。

### 下一步怎样证明客户价值？

选择一个客户确实存在、数据可获得且经典基线明确的问题，依次完成：

1. 用真实业务约束替换合成输入；
2. 与客户现有求解器比较解质量、运行时间和约束违反；
3. 完整验证业务冲突图与原子 interaction graph；
4. 接入带校准信息的目标机和真实执行通道；
5. 重复测量并报告成功率、误差、成本和规模边界。

在这些证据完成前，Demo 适合做技术路线和软件链路展示，不适合做生产收益承诺。

## 建议的源码阅读顺序

熟悉文章后，可以按以下顺序对照代码：

1. `domain/problem_api.py`：理解金融语义怎样包在统一 Problem 外层；
2. `domain/qubo_builder.py`：理解平方罚项和 slack 怎样展开；
3. `cases/portfolio.py`：从一个完整 Digital 场景理解目标与约束；
4. `cases/fraud_routing.py`：理解 Hybrid 业务冲突来源；
5. `cases/derivatives.py` 和 `pricing/derivatives.py`：理解经典与 Analog 边界；
6. `quantum/problem_executor.py`：理解模式建议、编译、运行和回退；
7. `api/presenters.py`：理解后端事实怎样转换为前端 JSON；
8. `frontend/src/components/`：理解五个页签怎样展示真实结果。

读代码时始终沿着一条变量追踪：它在业务输入中代表什么，怎样进入 QUBO 或图，编译后由哪个 term 和程序块承担，测量位串中的位置是什么，最后怎样解码回业务对象。这条链路就是 Demo 最核心的技术内容。
