# 中科酷原行业量子实验台 PRD

## 1. 产品定义

中科酷原行业量子实验台是基于 CASCAQit 的全场景行业量子实验平台。产品通过一个统一工作台承载金融、生物医药和材料科学领域，面向客户展示从领域问题、量子建模、编译执行到结果对照和审计证据的完整链路。

项目级名称统一如下：

| 层级 | 名称 |
|---|---|
| 对外产品 | 中科酷原行业量子实验台 |
| 工程与仓库 | `cascaqit-industry-workbench` |
| Python 分发包 | `cascaqit-industry-workbench` |
| 底层 SDK | CASCAQit |

金融、生物医药和材料科学是同级领域，不以任一领域名称代表整个项目。历史 `cascaqit_finance_demo` Python 包仅承担金融领域实现与兼容责任。

## 2. 产品目标

- 在一个应用中提供三个领域、15 个可执行场景。
- 用领域语言解释量子问题映射，而不是只展示线路和采样图。
- 同时覆盖 Digital、Hybrid D-A-D 和 Pure Analog 三种中性原子编程路径。
- 将量子结果、经典对照和数据参考分开保存与展示。
- 每次实验都能追溯到数据、输入、问题定义、编译计划、执行配置和结果哈希。
- 提供无需现场开发环境的 Windows 10/11 x64 离线交付物。
- 形成可复用的行业扩展框架，新领域不需要复制整套应用外壳。

## 3. 目标用户

| 用户 | 核心诉求 | 工作台提供的能力 |
|---|---|---|
| 行业客户与管理人员 | 了解量子计算可以进入哪些业务或研发环节 | 场景目录、结果摘要、对照分析和前沿价值 |
| 领域专家 | 判断建模是否保留领域约束和数据语义 | 领域输入、变量、Hamiltonian/QUBO、解码与约束复核 |
| 量子算法工程师 | 比较不同中性原子执行路径 | 模式分析、资源估算、线路、原子布局、波形和 counts |
| 售前与解决方案团队 | 稳定完成现场演示 | 固定预设、推荐配置、离线安装、统一讲解结构 |
| 研发与交付团队 | 扩展场景并复核发布质量 | 领域包边界、fixture manifest、自动测试和发布门禁 |

## 4. 当前场景范围

### 4.1 金融领域

共七个场景：多资产投资组合、交易结算、反欺诈调查编排、抵押品分配、日内流动性调度、企业授信额度配置、衍生品估值与风险情景。详细需求见[金融领域场景与界面设计](finance_demo_design.md)。

### 4.2 生物医药领域

共六个场景：小分子活性空间基态能量估计、靶点口袋与配体候选构象匹配、金属酶活性中心有效 Hamiltonian、小肽离散构象能景、RNA 二级结构集合、蛋白构象转变路径。详细需求见[生物医药与材料领域需求](biomedicine_demo_prd.md)。

### 4.3 材料科学领域

共两个场景：催化表面缺陷与吸附构型优化、缺陷晶格 Rydberg 动力学。前者展示 Hybrid/Digital QAOA，后者展示 Pure Analog AHS 时间动力学。

## 5. 核心用户流程

```text
进入统一工作台
  -> 选择一级领域
  -> 选择场景和预设
  -> 查看结构与数据来源
  -> 调整领域参数和实验配置
  -> 分析 Problem / Hamiltonian
  -> 执行推荐或对照配置
  -> 查看领域结果、量子实验和经典对照
  -> 查看审计证据或导出报告
```

领域切换只改变场景目录和领域视图，不重载整个应用。不同领域、场景、输入和执行配置的结果必须使用独立缓存身份，不能互相污染。

## 6. 信息架构与页面要求

### 6.1 全局层

- 顶部展示产品品牌和金融、生物医药、材料科学一级导航。
- 当前领域必须是第一视口中的明确状态。
- 左侧目录只显示当前领域场景，避免跨领域指标混排。
- 启动、加载、执行、失败和取消状态保持一致交互语义。

### 6.2 场景层

结果区统一提供以下视图，领域可以按实际内容裁剪：

| 视图 | 主要内容 |
|---|---|
| 领域结果 | 当前量子候选、关键指标、约束复核和未选原因 |
| 场景结构 | 资产/交易网络、分子与口袋、自旋网络、构象或晶格 |
| Problem 映射 | Pauli Hamiltonian、QUBO、变量、项来源和模式判断 |
| 量子实验 | 参数、线路、原子布局、波形、测量、counts 和重复统计 |
| 对照分析 | 经典优化、精确对角化、参考结构或独立时间演化 |
| 审计证据 | 数据版本、输入、编译、执行和结果身份 |

### 6.3 客户展示要求

- 页面文案聚焦问题映射能力、执行路径、结果可解释性和未来扩展价值。
- 不在主界面堆叠开发环境、内部实现状态或工程调试标签。
- 不使用经典结果替代失败的量子候选，也不把参考数据标记为量子输出。
- 每个场景的“前沿探索价值”必须与该场景对应，不使用跨页面重复套话。

## 7. 数据与审计要求

- 生物医药和材料 fixture 必须带版本化 manifest、数据来源、生成工具和 SHA-256。
- 打包后的 wheel 必须重新校验 manifest 声明的全部 artifact，不能只校验源码工作区。
- 输入、模式、算法、层数、shots、seed、搜索策略和优化预算共同组成运行身份。
- 报告至少保存 configuration hash、backend hash、outcome hash 和 report hash。
- 浏览器只消费结构化 API，不在前端重新实现领域能量或约束计算。

## 8. 交付要求

### 8.1 开发与源码

- Python 分发包：`cascaqit-industry-workbench`。
- 主命令：`cascaqit-industry-api`、`cascaqit-industry-demo`。
- 旧金融命令作为兼容入口保留，但不出现在新用户的主流程中。

### 8.2 Windows 离线包

- 文件名：`cascaqit-industry-workbench-windows-x64-py311.zip`。
- 支持 Windows 10/11 x64，不要求系统 Python、Node.js、管理员权限或安装时联网。
- 包含 `VERIFY.bat`、`INSTALL.bat`、`RUN.bat`、可重定位 CPython、完整 wheelhouse 和哈希清单。
- 安装器从 `bundle-info.json` 读取精确分发包版本，不在脚本中重复硬编码版本。

## 9. 发布验收

版本只有同时满足以下条件才能发布：

- Python 打包测试、Ruff、TypeScript、React 测试和生产构建通过。
- wheel 内全部 fixture artifact 与 manifest checksum 一致。
- Chromium 在桌面、窄桌面和移动视口完成八个生物医药/材料主场景验收。
- Windows runner 完成 ZIP 构建、文件校验、完全离线安装和 `RUN.bat` 启动。
- 安装后的 Windows 服务能够读取三个领域，并成功调用六个生物医药和两个材料结构分析接口。
- Release 资产大小和 GitHub 服务端 SHA-256 与验收制品一致。

## 10. 后续扩展原则

新领域必须提供独立领域包、场景目录、输入模型、Problem 适配器、结果解码器和测试；允许复用领域中性的执行器、审计工具、API 外壳和前端组件，不允许依赖其他业务领域的模型。达到三个以上新增领域并出现重复路由时，再引入注册式领域插件机制。
