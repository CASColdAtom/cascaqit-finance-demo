# 中科酷原行业量子实验台产品知识手册

## 1. 产品包含什么

中科酷原行业量子实验台是一套基于 CASCAQit 的行业量子应用工作台。当前版本包含金融、生物医药和材料科学三个领域、15 个可执行场景、52 个预设。

| 领域 | 场景数量 | 主要问题类型 | 主要算法 |
|---|---:|---|---|
| 金融 | 7 | 资产选择、任务调度、资源分配、风险情景筛选 | QAOA、QAA、经典定价 |
| 生物医药 | 6 | 电子结构、自旋关联、构象匹配、结构集合、转变路径 | VQE、QAOA、精确对角化、经典枚举 |
| 材料科学 | 2 | 缺陷与吸附构型优化、有效晶格时间演化 | Hybrid QAOA、Pure Analog AHS |

每个场景都包含五个组成部分：

1. 领域输入：金融业务条件、分子与构象数据或材料晶格与控制参数。
2. 问题模型：QUBO、Pauli Hamiltonian、MWIS 或 AHS Program。
3. 量子执行：Digital、Hybrid 或 Pure Analog 路线。
4. 领域结果：资产组合、任务安排、分子能量、结构路径或材料时间序列。
5. 对照与证据：经典对照、参考数据、约束复核和审计哈希。

### 常用模型和算法

| 名称 | 在 Demo 中的含义 |
|---|---|
| QUBO | 用二元变量表示“选或不选”，把目标和约束统一写成二次能量函数；能量较低的位串对应更好的候选。 |
| Pauli Hamiltonian | 用 Pauli 算符及其系数描述量子系统能量，是电子结构和有效自旋模型的直接输入。 |
| MWIS | 最大权重独立集：从带权图中选择总权重较高、彼此不冲突的节点。 |
| VQE | 变分量子本征求解器：调整参数化量子态，搜索 Hamiltonian 的低能状态。 |
| QAOA | 量子近似优化算法：在离散候选空间中采样低能组合。 |
| QAA | 量子绝热算法：连续改变 Hamiltonian，使系统向目标问题的低能状态演化。 |
| AHS Program | 模拟 Hamiltonian 程序：由原子位置、初态和 Rabi、Detuning、Phase 波形共同定义时间演化。 |
| D-A-D | Digital-Analog-Digital：数字线路、模拟演化、数字线路组成的 Hybrid 执行结构。 |

## 2. 三种量子执行路线

### Digital

Digital 使用数字量子线路表达问题。它适合全局约束较多、变量连接较稠密或 Hamiltonian 包含多种 Pauli 算符的任务。

本 Demo 中的典型场景包括投资组合、抵押品、流动性、授信额度、电子结构、金属活性中心、小肽、RNA 和蛋白转变路径。

### Hybrid

Hybrid 是数字—模拟—数字执行。平台先找出适合 Rydberg 原子相互作用表达的局域关系，将其放入 Analog core；目标函数和其余约束保留为 Digital residual。编译器会检查局域关系是否完整、是否出现额外相互作用，以及两部分系数之和是否与原始问题一致。

本 Demo 中的典型场景包括交易结算、反欺诈调查编排、构象匹配和材料缺陷吸附。

### Pure Analog

Pure Analog 不构造数字门。平台直接设置中性原子位置、初态、Rabi、Detuning 和 Phase 波形，使系统按目标 Hamiltonian 演化。

本 Demo 中的材料 Rydberg 动力学场景使用这条路线。衍生品风险情景也使用 Analog QAA，通过局域失谐承载风险权重，通过原子相互作用表达情景冲突。

## 3. Demo 怎样解决一个问题

所有场景遵循同一条处理流程：

```text
领域数据和参数
  -> 定义候选变量、目标和约束
  -> 生成 QUBO / Pauli Hamiltonian / AHS Program
  -> 分析 Digital、Hybrid、Analog 的适用性
  -> 编译并执行 VQE、QAOA、QAA 或 AHS
  -> 将测量结果解码为领域候选
  -> 重新检查原始领域约束
  -> 展示经典对照、参考数据和审计证据
```

这条流程有三个关键特点：

- 量子模式由当前问题结构决定，而不是固定写在场景名称中。
- 量子能量较低不自动等于领域方案可用，解码后还会重新检查业务或科学约束。
- 量子结果、经典对照和参考数据保持独立身份，便于比较和复核。

## 4. 六类结果页面是什么意思

不同领域使用相同的页面框架，具体图表随场景变化。

| 页面 | 表达的内容 | 应关注什么 |
|---|---|---|
| 领域结果 | 把量子位串或测量值还原成业务、分子、构象或材料结果 | 当前候选、关键指标、可行性和约束状态 |
| 场景结构 | 展示输入数据之间的关系 | 资产相关性、交易冲突、分子相互作用、状态网络或材料晶格 |
| Problem 映射 | 说明领域问题怎样变成量子问题 | 变量、QUBO/Pauli 项、约束来源、推荐模式和资源规模 |
| 量子实验 | 展示实际量子执行内容 | 数字线路、原子布局、控制波形、参数历史、测量和 counts |
| 对照分析 | 将量子结果与独立方法或参考数据比较 | 精确对角化、经典枚举、动态规划、最短路或数值时间演化 |
| 审计证据 | 保存一次运行的身份链 | 数据版本、输入、编译、执行配置、结果和报告哈希 |

`counts` 是有限次数测量得到的位串频次。它需要经过场景解码器，才能转换为资产、交易、构象、配对或路径。参数历史表示算法实际评估过的参数点及其目标值，用于说明优化过程，不是领域结果本身。

## 5. 金融领域

### 5.1 多资产投资组合优化

#### 场景和问题

从八项候选资产中选择等权组合，同时平衡预期收益、协方差风险、持仓数量、行业集中度和防御资产下限。

#### 原理、算法和求解过程

每项资产对应一个二元变量，`1` 表示入选。预期收益形成线性奖励，协方差形成二次风险项。固定持仓数、行业上限和防御资产下限通过罚项与辅助变量写入 QUBO。

协方差连接稠密，约束覆盖多个资产，不适合只用局域原子相互作用表达，因此推荐 Digital QAOA。算法采样得到资产位串后，系统重新计算收益、波动率，并复核三类组合约束。

#### 预设

| 预设 | 表达的条件 |
|---|---|
| 基准市场 | 标准收益、风险和约束基线 |
| 利率上行 | 提高风险权重并增加防御配置要求 |
| 权益回撤 | 进一步提高风险权重和防御资产下限 |
| 商品冲击 | 调整风险偏好与行业集中度条件 |

#### 参数

| 参数 | 范围 | 含义 |
|---|---:|---|
| 风险权重 | 0.20～0.85 | 越高越重视协方差风险；剩余权重用于收益 |
| 持仓数量 | 3、4、5 | 组合必须选中的资产数量 |
| 单行业上限 | 1、2、3 | 同一行业最多入选的资产数量 |
| 防御资产下限 | 0、1、2 | 消费、债券、黄金、医药等防御资产至少入选的数量 |

推荐配置为 Digital QAOA、32 shots、`p=1`、连续优化、12 次评估、2 个优化起点。

#### 结果页面

- 领域结果：显示入选资产、预期收益、组合波动率、持仓数和约束状态。风险收益散点中的高亮点是当前组合。
- 场景结构：相关性矩阵展示资产之间的正负相关及强弱，说明风险项为什么形成稠密连接。
- Problem 映射：展示收益项、协方差项、持仓与行业约束及辅助变量怎样进入 QUBO。
- 量子实验：展示 QAOA 线路、参数优化历史和资产位串 counts。
- 审计证据：保存输入权重、候选资产、编译配置和结果身份。

#### 体现的优势

收益、风险和多项组合约束进入同一个模型。结果不只给出量子能量，还直接还原成资产组合，并逐项解释约束是否满足。

### 5.2 交易结算批次优化

#### 场景和问题

从十笔待结算指令中选择当前批次，兼顾结算金额、业务优先级、币种流动性、批次容量、前置依赖和交易冲突。

#### 原理、算法和求解过程

每笔交易对应一个二元变量。金额和优先级形成目标奖励；冲突交易不能同时入选；子交易入选时必须包含前置交易；每个币种的流动性占用不能超过上限。

局域交易冲突进入 Rydberg Analog core，金额、优先级、依赖、流动性和辅助变量保留在 Digital residual，因此推荐 Hybrid QAOA。测量位串解码为交易批次后，系统重新检查批次上限、三币种流动性、依赖和冲突。

#### 预设

| 预设 | 表达的条件 |
|---|---|
| 日常批次 | 标准交易价值、流动性和冲突关系 |
| 重点客户优先 | 提高业务优先级相对结算金额的权重 |

#### 参数

| 参数 | 范围 | 含义 |
|---|---:|---|
| 金额权重 | 0.20～0.80 | 名义金额在交易价值中的占比 |
| 优先级权重 | 0.20～0.80 | 业务优先级在交易价值中的占比 |
| 批次上限 | 5、6、7、8 | 当前批次最多入选的交易数 |
| 约束罚项倍数 | 1.2～3.5 | 硬约束相对业务目标的能量强度 |

推荐配置为 Hybrid QAOA、32 shots、`p=1`、预设参数。

#### 结果页面

- 领域结果：显示入选交易、结算金额、交易数量、业务目标和约束状态。
- 场景结构：实线表示不可同批结算的冲突，虚线箭头表示前置依赖。
- Problem 映射：`core coverage` 显示冲突边是否全部进入 Analog；missing 和 unexpected 用于检查漏边和额外相互作用。
- 量子实验：展示 D-A-D 结构、原子对布局、控制波形、Digital residual 线路和交易位串 counts。
- 审计证据：记录交易输入、Hybrid 拆分、编译结果和业务解码结果。

#### 体现的优势

Hybrid 按约束性质分工。局域冲突由原子相互作用表达，全局流动性和依赖仍保留完整数字约束，同时提供系数守恒证据。

### 5.3 反欺诈调查任务编排

#### 场景和问题

在有限调查席位下，从十二条告警中优先安排高风险、高金额和等待时间较长的任务，并控制同一实体的并行调查数。

#### 原理、算法和求解过程

每条告警对应一个二元变量。风险分、涉案金额和等待时间形成加权价值；席位数量形成精确数量约束；同一账户、设备或商户关联的告警形成冲突。

共享实体冲突进入 Analog core，其余目标和席位约束进入 Digital residual，默认推荐 Hybrid QAOA。当单实体并行上限放宽后，局域冲突可能消失，系统会重新判断 Digital 更合适。

#### 预设

| 预设 | 表达的条件 |
|---|---|
| 账户接管 | 共享账户或设备形成的调查冲突 |
| 团伙交易 | 多实体关联并提高风险权重 |
| 商户异常 | 更重视涉案金额并放宽部分实体并行限制 |

#### 参数

| 参数 | 范围 | 含义 |
|---|---:|---|
| 风险权重 | 0.10～0.80 | 风险分在告警价值中的重要性 |
| 金额权重 | 0.10～0.80 | 涉案金额在告警价值中的重要性 |
| 时效权重 | 0.10～0.80 | 等待时间在告警价值中的重要性 |
| 调查席位 | 3、4、5、6 | 必须安排的调查任务数量 |
| 单实体并行上限 | 1、2 | 同一实体允许同时调查的任务数量 |

推荐配置为 Hybrid QAOA、32 shots、`p=1`、预设参数。

#### 结果页面

- 领域结果：显示入选告警、风险覆盖率、金额覆盖率、预计工时和约束状态。
- 场景结构：告警与账户、设备、商户的网络说明冲突来源。
- Problem 映射：展示三类目标权重、席位约束、共享实体冲突和推荐模式变化。
- 量子实验：展示冲突原子布局、Hybrid 波形、数字剩余项和告警位串 counts。
- 审计证据：记录告警输入、实体关系、模式分析和解码结果。

#### 体现的优势

平台能够根据业务参数变化重新选择执行路线。结果同时说明调查资源覆盖了哪些风险，以及哪些实体冲突影响了安排。

### 5.4 抵押品分配优化

#### 场景和问题

从“抵押品批次—保证金需求”候选方案中，为 CCP 和双边需求选择分配，平衡覆盖质量、融资成本、资格和批次唯一性。

#### 原理、算法和求解过程

一个变量代表一条完整分配方案。业务价值形成奖励，资金成本形成惩罚。每个需求必须恰好选择一项，同一资产批次不能重复分配。

问题主体是多个需求组的精确选择约束，因此推荐 Digital QAOA。系统将量子位串解码成抵押品流向，再检查需求覆盖、资格和批次冲突。

#### 预设

| 预设 | 表达的条件 |
|---|---|
| 日常补缴 | 标准资格、覆盖和资金成本 |
| 市场波动 | haircut 条件变化并提高覆盖质量权重 |
| 保留优质资产 | 提高资金成本权重，倾向保留高流动性资产 |

#### 参数

| 参数 | 范围 | 含义 |
|---|---:|---|
| 业务价值权重 | 0.20～0.85 | 覆盖质量在目标中的重要性 |
| 成本权重 | 0.15～0.80 | 资金占用成本在目标中的惩罚强度 |

推荐配置为 Digital QAOA、64 shots、`p=1`、连续优化、12 次评估。

#### 结果页面

- 领域结果：显示入选分配、总业务价值、总成本、覆盖单位和约束状态。
- 场景结构：Sankey 流图连接抵押品批次与保证金需求，流宽表示覆盖单位。
- Problem 映射：展示价值、成本、需求组精确约束和批次冲突怎样进入 QUBO。
- 量子实验：展示 Digital QAOA 线路、参数历史和分配位串 counts。
- 审计证据：记录候选资格、权重、QUBO 和最终分配身份。

#### 体现的优势

变量直接对应可解释的分配方案。页面能从量子位串追溯到“哪批资产分给哪个需求”，并验证批次没有重复使用。

### 5.5 日内流动性调度

#### 场景和问题

从不同时点、币种和工具的融资动作中选择组合，满足最低覆盖、动作数量、币种集中度、渠道冲突和前置依赖。

#### 原理、算法和求解过程

每个融资、划拨或换汇动作对应一个二元变量。覆盖价值和融资成本形成目标；动作数量、最低覆盖和单币种上限形成全局约束；部分动作存在冲突或时序依赖。

有向依赖和全局覆盖是问题主体，因此推荐 Digital QAOA。量子位串被解码为按时间排序的资金动作，并重新检查五类约束。

#### 预设

| 预设 | 表达的条件 |
|---|---|
| 基准流动性 | 标准跨时点、跨币种动作调度 |

#### 参数

| 参数 | 范围 | 含义 |
|---|---:|---|
| 覆盖价值权重 | 0.20～0.85 | 流动性贡献在目标中的重要性 |
| 成本权重 | 0.15～0.80 | 融资成本的惩罚强度 |
| 动作数量 | 3、4、5 | 必须选择的资金动作数量 |
| 最低覆盖单位 | 8～16 | 所选动作必须达到的最低流动性覆盖 |
| 单币种上限 | 1、2、3 | 同一币种最多入选的动作数量 |

推荐配置为 Digital QAOA、128 shots、`p=1`、预设参数。

#### 结果页面

- 领域结果：显示入选动作、覆盖价值、融资成本、资金单位和约束状态。
- 场景结构：时间轴展示候选动作的时点和规模，阶梯线展示各币种候选资金的累计分布。
- Problem 映射：展示价值、成本、数量、最低覆盖、币种上限、冲突和依赖。
- 量子实验：展示数字线路、参数点和资金动作位串 counts。
- 审计证据：记录输入动作、时序规则、执行参数和调度结果。

#### 体现的优势

时间、币种、容量和依赖可以进入同一个组合优化问题。结果保留动作顺序和每项约束的检查信息。

### 5.6 企业授信额度配置

#### 场景和问题

在已准入企业候选中配置额度档位，平衡风险调整价值、资本成本、资本使用上限、额度数量和行业集中度。

#### 原理、算法和求解过程

每个“企业—额度档位”对应一个变量。风险调整价值形成奖励，资本成本形成惩罚；同一企业档位互斥，资本和行业上限使用辅助变量表达。

资本预算和行业集中度是全局结构，因此推荐 Digital QAOA。推荐配置使用两层线路。测量结果解码后，系统复核额度数量、资本、行业和互斥约束。

#### 预设

| 预设 | 表达的条件 |
|---|---|
| 稳健配置 | 平衡业务价值、资本和行业集中度 |
| 收益优先 | 提高价值权重并放宽可用资本上限 |

#### 参数

| 参数 | 范围 | 含义 |
|---|---:|---|
| 风险调整价值权重 | 0.20～0.85 | 业务价值在目标中的重要性 |
| 资本成本权重 | 0.15～0.80 | 资本代价的惩罚强度 |
| 额度数量 | 3、4、5 | 必须配置的额度档位数量 |
| 资本使用上限 | 8～14 | 组合允许使用的最大资本单位 |
| 单行业上限 | 1、2、3 | 同一行业最多入选的额度档位数量 |

推荐配置为 Digital QAOA、128 shots、`p=2`、预设参数。

#### 结果页面

- 领域结果：显示入选企业与档位、风险调整价值、资本成本、资本单位和约束状态。

### 5.7 衍生品定价与风险情景

#### 场景和问题

#### 原理、算法和求解过程

九个压力点组成最大权重独立集问题。绝对 P&L 形成节点权重，网格上下左右相邻表示信息冲突。权重进入 Analog 局域失谐，冲突进入 Rydberg interaction，使用 Analog QAA 选择情景组合。

| 预设 | 定价方法与特点 |

| 执行价 | 70～140 | 合约执行价格 |
| 波动率 | 0.08～0.60 | 年化常波动率假设 |
| 无风险利率 | 0～0.10 | 连续复利无风险利率 |
| 期限 | 0.25～2 年 | 距离到期的时间 |
| 障碍价 | 105～180 | 上敲出障碍期权的触发价格 |

- 场景结构：展示周期晶格、缺陷候选、吸附位点、取向和当前构型。
- Problem 映射：展示缺陷与吸附联合变量、系数账本、周期/对称约束和 Hybrid 拆分。
- 量子实验：展示原子布局、Hybrid 波形、Digital residual、QAOA 参数和构型 counts。
- 对照分析：分别显示量子候选、完整经典枚举和离线参考。
- 审计证据：记录材料数据版本、逻辑晶格、编译布局、QUBO 和构型结果。

#### 体现的优势

缺陷与吸附不再分开筛选，而是进入同一个优化问题。材料晶格坐标和量子编译坐标保持独立，可同时检查领域结构和量子映射。

### 7.2 材料缺陷晶格中的 Rydberg 动力学与量子淬火

#### 场景和问题

观察缺陷或局域杂质怎样影响有效晶格中的激发传播、逐位点占据、磁化和二点关联随时间变化。

#### 原理、算法和求解过程

场景从四位点声明初态出发，设置 Rydberg 原子位置和 Rabi、Detuning、Phase 波形，生成 AHS Program。每个请求时刻执行覆盖 `[0,t]` 的前缀程序，得到该时刻的占据与关联。

这是一条 Pure Analog AHS 路线，不包含 QUBO、数字门或 Digital residual。系统还使用独立 DOP853 数值积分计算同初态、同 Hamiltonian 的对照曲线。

#### 预设

| 预设 | 动力学条件 |
|---|---|
| 理想晶格基准 | 无缺陷四位点传播基线 |
| 单空位传播 | 观察单个缺陷对传播的影响 |
| 多缺陷 / 局域杂质 | 观察多缺陷和局域偏置引起的局域化趋势 |

#### 参数

| 参数 | 范围 | 含义 |
|---|---:|---|
| 演化时长 | 0.2～2.0 μs | 时间演化的终止时刻 |
| Rabi 峰值 | 0.5～4.0 rad/μs | 驱动基态与 Rydberg 态转换的最大强度 |
| 终态失谐 | -4.0～4.0 rad/μs | 演化结束时的能级偏置 |
| 采样时刻 | 5～21 个奇数点 | 时间序列包含的观测时点数量 |

推荐配置为 Pure Analog AHS、每个时点 128 shots、9 个采样时刻、预设波形。

#### 结果页面

- 领域结果：显示各时刻逐位点占据、总激发、磁化和二点关联的时间序列。
- 场景结构：分别展示材料晶格、四位点活动窗口和 Rydberg 寄存器坐标。
- Problem 映射：展示 AHS Program、初态、原子位置、相互作用、波形和采样时刻。
- 量子实验：展示 Rabi、Detuning、Phase 控制波形、终态 counts 和逐时点程序身份。
- 对照分析：将 CASCAQit AHS 时间序列与独立 DOP853 数值曲线比较。
- 审计证据：记录初态、程序、每个时点的状态与结果 hash。

#### 体现的优势

该场景直接展示时间分辨的 Pure Analog 演化。材料有效模型、量子寄存器、控制波形、时间序列和数值对照在同一个实验中完整关联。

## 8. 公共量子执行参数

领域参数决定“要解决什么问题”，量子执行参数决定“怎样运行量子算法”。每个场景已经提供推荐配置。

| 参数 | 页面选项 | 含义 | 对结果的影响 |
|---|---|---|---|
| 执行模式 | Digital、Hybrid、Analog | 选择量子问题的执行路线 | 只有通过当前问题分析的模式可以运行 |
| 算法 | Recommended、QAOA、VQE、QAA | 选择组合优化、低能态搜索或量子绝热演化算法 | 不同场景只开放适用算法 |
| Shots | 16、32、64、128、256、512 | 同一量子程序重复测量的次数 | 越高通常统计越稳定，运行时间和测量成本也更高 |
| Seed | 0、1、3、5、6、7、8、19、23、41 | 控制参数初值和采样随机序列 | 相同输入、配置和 seed 用于复现结果 |
| 层数方式 | 固定、自动选择 | 固定线路深度或在允许范围内比较层数 | 自动选择会比较多个深度的目标改善 |
| 变分层数 | 场景允许的 `p=1～3` | QAOA/VQE 参数化线路深度 | 层数增加会增加参数和线路复杂度 |
| 参数搜索 | 预设、二维网格、固定 seed 采样、连续优化 | 寻找线路参数的方法 | 决定实际评估哪些参数点 |
| 评估预算 | 场景允许的参数点数量 | 参数搜索最多评估的次数 | 预算增加会扩大搜索，但也增加运行时间 |

| 独立运行 | 1、3、5 | 使用递增 seed 重复完整分析、编译和执行 | 用于观察候选可行率和结果稳定性 |

## 9. Demo 体现的整体优势

### 一个工作台覆盖三类行业问题

金融组合优化、生物分子与构象研究、材料构型和时间动力学共用一套分析、执行、对照和审计流程，各领域仍保留独立的数据、指标和页面表达。

### 量子路线与问题结构匹配

平台不会给所有场景固定同一种算法。Digital 处理稠密和全局结构，Hybrid 拆分局域相互作用与剩余约束，Pure Analog 直接表达 Hamiltonian 时间演化。

### 从量子输出回到领域结果

系统不只展示线路和位串。金融场景还原资产、交易和资源配置；生物医药场景还原能量、匹配、构象和路径；材料场景还原缺陷吸附构型和时间序列。

### 对照结果身份清晰

量子结果、经典算法和数据参考分别保存。页面可以比较不同方法，但不会把一种结果改写成另一种结果。

### 每次运行可以复核

数据版本、输入、问题模型、编译、执行配置和结果都进入审计链。相同输入和配置可以复查，不同参数产生的新结果也不会混入旧实验。
